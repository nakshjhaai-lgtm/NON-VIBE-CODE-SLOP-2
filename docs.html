How the editor works

Five minutes to your first export. Everything below applies to version 2.4.0.

Last updated 24 August 2026

Install

The editor runs at editor.pixelforge.studio as an installable web app, so there is nothing to download for the editor itself. The command line tool is optional and only used to export from a script.

Terminal 
# Optional: export from a build script
npm install --save-dev @pixelforge/cli

npx pixelforge export ./hero.pforge --target react --out ./src
System requirement

The viewport needs WebGL2. Chrome and Edge 113 or newer, Safari 16.4 or newer, or Firefox 115 or newer. Without WebGL2 the editor still opens and shows a static poster image where the viewport would be.

Scene graph

A scene is a tree. Cameras, lights and meshes are nodes; transforms are inherited; names are stable across exports so the generated code stays readable.

scene.pforge.json 
{
  "version": "2.4.0",
  "nodes": [
    { "name": "Mesh_01", "geometry": "geodesic",
      "position": [0, 0, 0], "rotation": [-29, 34, 0] }
  ]
}

Node materials

A material is a directed graph of nodes. Each node becomes one uniform in the exported shader, which is why the graph stays small enough to read after export.

  • PBR base, fresnel, gradient and noise nodes cover most surfaces.
  • Custom GLSL nodes are allowed and are emitted verbatim.
  • Every node has a cost estimate shown in the inspector footer.

Scroll animation

Keyframes live on a timeline measured in page scroll percentage rather than seconds, so motion stays in step with how fast someone scrolls.

Export targets

Six targets, all generated from the same scene file. Framework exports emit source you own; there is no runtime dependency to keep.

Performance budget

The renderer keeps a frame budget of 16 ms on a 2019 laptop class GPU. When a scene exceeds it, the editor says so in the viewport overlay instead of quietly dropping frames.

  • Draw calls are batched per material, not per mesh.
  • Shadow maps are capped at 2048 px and one directional light.
  • Physics runs on a worker thread and is baked to keyframes on export.
  • Auto rotation stops when the tab is hidden or the viewport scrolls away.

Case study: the viewport on this page

The rotating object at the top of the home page is not a video, a GIF or a screenshot. It is a software renderer that projects 42 vertices and 120 edges onto a 2D canvas, drawn with depth cued line weights.

Measured on this build
Property Value
Renderer code 4 KB uncompressed
Dependencies 0
Animation transform and line alpha only
Reduced motion Stops, renders one frame
Offscreen or hidden tab Loop cancelled
Why not WebGL

A 120 edge wireframe does not need a GPU pipeline, and a 2D canvas keeps the page at zero third-party scripts. The exported scenes are the ones that use WebGL2.
